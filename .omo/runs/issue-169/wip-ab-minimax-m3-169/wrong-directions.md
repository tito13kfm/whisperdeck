## Background explore agent — caught an additional kind-allowlist site

The explore agent (Qwen3.5-4B via Lemonade) took 7m46s to complete —
well over the typical local-agent budget for a focused scan, and the
output is partial: the agent got stuck on Windows path quoting
(`/c/Claude/...` vs `C:\Claude\...`) and on hitting a 60s timeout on
broad `*.py` greps. Despite that, it surfaced one site I had not
enumerated in my own sibling-sweep:

- `app.py:2128` — `if kind not in ("correction", "summary", "rediarize",
  "format_markdown", "format_email", "format_coding_prompt",
  "classify_intent")` — a hardcoded allowlist for the
  `/api/transcripts/{id}/runs/{kind}` history endpoint.

This is the SAME shape as the upload and PATCH kind allowlists, and
is the kind of allowlist a sibling-sweep is supposed to catch. I had
not grep'd for it because it lives in the runs route and my own
sibling-sweep started from the upload-route allowlist as the seed.
Added `voice_note` to the list; would have shipped without it
otherwise and a `GET /runs/voice_note` would have returned 400 instead
of the run history. Saved by the agent; logged here so future runs
of this command budget more time for the sibling-sweep.

Cost: 7m46s of local GPU time at zero cloud spend, but a real
opportunity cost vs. my own 5-minute manual sweep that missed this
site. Net positive: the bug class ("hardcoded enum in a route I
forgot to read") was the kind of thing the explore agent is good
at, and the path-quoting struggle is a one-time cost. Worth running
again for future issues of similar surface area.

## Two test failures, both my own design errors

The first run of the new tests had two failures. Both were
test-design errors, not implementation bugs.

1. `test_classify_raises_on_unsupported_provider` — I asserted
   `pytest.raises(ProviderError)` on `classify_voice_note`. The
   function has a never-raise contract (mirrors `classify_intent`
   in `services/reformatting.py`); any error falls back to
   `DEFAULT_NOTE_TYPE` so the chain still produces a useful
   general-type structure. The test was modeling on
   `format_as_markdown`, which IS raise-by-design, and missed that
   `classify_*` is intentionally different. Fixed by changing the
   assertion to `assert result == DEFAULT_NOTE_TYPE`.

2. `test_upload_forces_diarize_off_for_voice_note_despite_client`
   — the `_upload` stub I wrote set `diarize_requested=True` on
   the row directly. The pipeline's force-off happens upstream
   (line 974 in app.py), but my stub was bypassing it. Fixed by
   dropping the `diarize_requested` assignment from the stub so
   the test actually observes what the pipeline does.

Both failures are documented in `token-usage.md` under "What would
cut it next time" — listing them here as well so a future run can
see they're the same pattern (modeling a test on the wrong existing
test).
