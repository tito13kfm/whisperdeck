Findings — bugs / confirmed defects

F1 · Second browser tab silently bricks the first (CSRF token)

bugmajorerror-recovery

generate_csrf_token (security.py:19-23) writes a NEW random token on every call; GET /api/csrf-token (app.py:315) calls it unconditionally. Frontend fetches once at boot and caches it (rack.js:427); api() never refreshes+retries on a 403 (rack.js:202).

Failure: opening a second tab (its boot rotates the server token) makes the first tab's every mutation fail 403 until manual reload. Only signal is a 4.2s toast with the raw string "Invalid or missing CSRF token"; UI otherwise looks idle.

Fix: on 403-CSRF, call refreshCsrfToken() + retry once, and/or make the session token stable across reads.

F8 · Transcribe deck "Auto-correct" toggle is a dead control

bugmajordead-control

Deck showed Auto-correct OFF yet correction auto-ran on every upload. ctl-autocorrect (rack.js:1104) only flips client var S.autoCorrect; startJob (rack.js:1316-1330) never sends it. Server keys purely off the global user_settings.auto_correct (default true, app.py:835). Two identically-named switches, one inert.

Fix: send + honor the deck toggle per-job, or remove it and point to the Service-panel global.

F3 · Voice match collapsed two diarized speakers into one profile, no confidence / undo

bugmajorquality

Second upload's "Match now" labeled all 69 segments (incl. the 16 "Speaker 2" lines) as the single enrolled "Alice". No per-speaker confidence shown, no result summary, no undo short of full re-diarize. MFCC fallback backend (open issue #38) over-matches; UI offers no guard.

Related: issue #38 (pyannote embedding backend). Fix: show match confidence per speaker + allow reject.

F19 · "Add context" reports a dead LLM provider as success ("No new terms found")

bugmajormasked-failure

With the correction provider pointed at an unreachable address, adding a context doc full of proper nouns returned the success-shaped toast "No new terms found" (200 OK). extract_hotwords_from_doc (correction.py:139-165) wraps the LLM call in try/except Exception: return [], so a transport failure is indistinguishable from a genuine empty extraction. Inconsistent with correction/summarize, which DO surface "failed".

Fix: distinguish provider/transport errors from empty results; toast a reachability error on the former.

F16 · Transcribe deck retains the previous session's transcript state across logout/login

bugmajorstale-state

After logout + register of a fresh zero-data account, Deck B still read "Transcript written — press ⏹ to open it" and its key still targeted the prior user's transcript id. Clicking → toast "Transcript not found" AND the detail page rendered a stale header for the previous user's file ("e2e_multispeaker.mp3"). Client state (last-finished id, deck status) is not cleared on logout.

Fix: clear detail/deck state (and any localStorage) on logout; guard the open-finished key against a cross-user id.

Findings — missing feedback / progress

F2 · Session-start snapshot never refreshes — Monitor, nav badges, storage meter (the "blank Monitor" symptom)

bugmajorstale-ui

Monitor (stat tiles + "Recent signals"), nav badges (Tape library, Voice roster), and the rail Storage meter render from data fetched once at login. After creating 3 transcripts + 1 voice profile, Monitor still showed the full empty state ("No signals yet — load a tape") and badges read "00". A badge self-corrects only when its own page is visited. Since Monitor is the landing page, returning to it after doing work falsely shows an empty account.

This is the reported "blank Monitor on first load" symptom — reframed: genuine first-load is a correct empty state (see F18); the blankness is this stale snapshot after data exists. Fix: refresh dashboard/badges on navigation or via a shared store.

F4 · Long synchronous operations give no progress affordance

majormissing-feedback

"Enroll marked clips" ran 10-20s with the modal open and the button silently disabled — no spinner/progress, looks frozen. "Match against voice roster" ran ~34s with only an initial 4.2s toast. The re-transcribe/re-run pickers also show a ~1-2s blank gap while their model list loads. Any withBusy() op >2s lacks a visible busy state beyond the disabled attribute.

Fix: spinner/progress text on long ops; skeleton/placeholder while picker options load.

F6 · Job failures notify passively only (residue of closed #5)

majormissing-feedback

A failed summary produced NO toast; the failure was visible only by visiting the Summary tab ("Summary failed — <raw JSON parse error>") or the Queue ("ERR failed" + Rerun/Clear). Tab/queue surfacing is the #5 fix working; an active failure notification is still absent, and the raw parser error string is shown verbatim.

Fix: toast on background-job failure; humanize the error string.

F9 · Mic-permission-pending state looks dead

majormissing-feedback

While the browser mic-permission prompt is pending, the only cue is a 4.2s "Requesting microphone…" toast; after it expires the monitor reads STANDBY and the Rec key looks idle, with nothing persistent. A user who misses the browser's permission chip sees a dead app.

Fix: persistent "waiting for microphone permission…" state until grant/deny resolves.

Findings — UI / UX / copy

F10 · Live-capture recording UX gaps

minormissing-feedback / copy

  • No elapsed-time counter during recording (scope animates + REC LED lit, but no duration).
  • Status line claims "mic (L) + system (R)" even when only mic was granted; should reflect actual channels.
  • The control that OPENS a finished transcript is the ⏹ "Stop/Eject" key — label contradicts action (guidance text compensates).

F11 · Detail-header action overload

minorui

11 identically-styled buttons in one row (Re-transcribe … Delete), including a red Delete in the same strip. No grouping or hierarchy; the "which button do I press to proceed" problem.

F14 · Rail status reads "Working" on an idle fresh account

minormislabeled

Bottom rail shows "Working" persistently even when idle. If it means "operational", the word reads as "busy".

F15 · Inconsistent job-kind labels in Queue

minorcopy

"CORRECT" (styled) vs "voice_match" (raw underscored enum) in the same list.

F5 · No password policy (flag for review, not a defect)

minorproduct

Register accepts "abc" silently; no confirm field, no requirements shown. Confirmed by-design: /api/register (app.py:333) checks non-empty only. Flag for product decision, not a bug.

Findings — accessibility / info exposure

F13 · Nixie "ghost" digits leak into the accessibility tree

minora11y

Stat tiles, nav badges, and percent readouts expose ghost "8" segments to assistive tech: "Minutes transcribed" reads "80" when the value is 0; "100%" reads "8 1 8 0 8 0 8 %". Screen readers get garbage.

Fix: aria-hidden on the ghost-digit spans.

F17 · Orphaned uploads are global across users (visible + deletable); absolute paths exposed

minordata-isolation

/api/files (app.py:1022-1064) correctly scopes referenced files per user, but UPLOAD_DIR is one shared directory: the "orphaned" branch lists every unreferenced file regardless of uploader, and /api/files/delete lets any user delete them. A fresh account saw the prior user's orphaned live-capture .webm. Full absolute server paths are shown in the UI for every row.

Related: open log Observation #11 (orphan classification). Confirm intended ownership model; if per-user, scope the orphan scan by owner. Narrowed from an earlier over-broad "sees another user's files" reading.

F12 · Console noise on every fresh load

minorcosmetic

favicon.ico 404 and a pre-auth /api/me 401 are logged as console errors on load. Cosmetic, but reads as broken in devtools.
